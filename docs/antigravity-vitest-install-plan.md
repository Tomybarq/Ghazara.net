# خطة تثبيت Vitest لمشروع Ghazara Sales App

> **موجّهة إلى Antigravity:** نفّذ هذه الخطة خطوة بخطوة. لا تعتبر المهمة مكتملة بناءً على وجود السطر في `package.json` فقط؛ يجب التحقق من التثبيت الفعلي، ملف القفل، وتشغيل أمر الاختبار.

**الهدف:** تجهيز بيئة اختبار Unit Tests لمشروع React + TypeScript + Vite باستخدام Vitest، دون تغيير سلوك التطبيق أو إدخال Backend.

**النطاق:** تثبيت Vitest والتحقق من جاهزيته فقط. لا تنشئ اختبارات Domain أو تعدّل منطق التطبيق ضمن هذه المهمة إلا إذا تطلب التحقق إصلاحاً صغيراً موثقاً.

**المسؤوليات:**

- مدير الحزم: npm على Windows.
- أمر التثبيت المعتمد: `npm.cmd install -D vitest`.
- أمر الاختبار المعتمد: `npm.cmd run test`.
- لا تستخدم `npm` مباشرة لأن PowerShell قد يحاول تشغيل `npm.ps1` ويمنعه Execution Policy.

## الحالة الحالية التي يجب أخذها في الاعتبار

الفحص الأولي أظهر أن `package.json` يحتوي حالياً على:

- `vitest: ^5.0.3` داخل `devDependencies`.
- سكربت اختبار: `"test": "vitest run"`.

لذلك يجب تنفيذ الخطة بطريقة آمنة وقابلة لإعادة التشغيل. إذا كان Vitest مثبتاً فعلاً ومتزامناً مع `package-lock.json`، لا تعِد تثبيته بلا حاجة؛ اكتفِ بالتحقق وسجّل أن التثبيت كان موجوداً مسبقاً.

## القيود العامة

1. اقرأ `AGENTS.md` و`docs/architecture.md` قبل التنفيذ.
2. حافظ على Arabic RTL وعدم تغيير واجهة المستخدم.
3. لا تستخدم `any` ولا تخفِ أخطاء التثبيت أو الاختبار.
4. لا تضف `@testing-library/*` أو `jsdom` أو إعدادات React Testing Library في هذه المهمة؛ هذه تبعيات لمهمة لاحقة.
5. لا تغيّر نسخة Vitest الموجودة إلا إذا كشف npm عن تعارض واضح؛ عندها سجّل السبب قبل التغيير.
6. لا تنفّذ Git commit أو push إلا وفق تعليمات المستودع وآلية العمل المعتمدة لدى الفريق.

## Task 1 — فحص الحالة قبل التثبيت

**الملفات:** لا توجد تعديلات متوقعة.

- [ ] تحقّق من نسخة Node وnpm:

```powershell
node --version
npm.cmd --version
```

- [ ] تحقّق من تعريف الحزمة:

```powershell
npm.cmd ls vitest --depth=0
```

- [ ] تحقّق من وجود `vitest` في `package.json` ووجود `test` script.
- [ ] افحص حالة المستودع والملفات المعدّلة قبل التنفيذ إن كان Git متاحاً:

```powershell
git status --short
```

**نتيجة متوقعة:** يتم تحديد إحدى الحالات التالية:

| الحالة | الإجراء |
|---|---|
| Vitest موجود في `package.json` و`npm.cmd ls` ينجح | لا تعِد التثبيت؛ انتقل إلى Task 3 |
| Vitest موجود في `package.json` لكن غير موجود محلياً أو غير متزامن | نفّذ Task 2 |
| Vitest غير موجود | نفّذ Task 2 |
| npm أو Node غير متاح | توقف وسجّل الخطأ؛ لا تعدّل الملفات يدوياً |

## Task 2 — تثبيت Vitest عند الحاجة

**الملفات المتوقعة للتعديل:**

- Modify: `package.json`
- Modify: `package-lock.json`

- [ ] نفّذ الأمر التالي من جذر المشروع `D:\sales-app` فقط:

```powershell
npm.cmd install -D vitest
```

- [ ] انتظر اكتمال الأمر ولا تستخدم `--force` أو `--legacy-peer-deps` إلا بعد توثيق خطأ dependency resolution صريح.
- [ ] تحقّق أن `vitest` ظهر داخل `devDependencies` وأن `package-lock.json` تم تحديثه بصورة طبيعية.
- [ ] لا تقم بتعديل `node_modules` يدوياً.

**نتيجة متوقعة:** ينتهي npm برمز خروج `0`، وتصبح حزمة Vitest قابلة للاستدعاء من المشروع.

## Task 3 — التحقق من التشغيل

**الملفات:** لا توجد تعديلات متوقعة، إلا إذا احتاج Vitest إلى ملف إعداد مبرر ومثبت بخطأ واضح.

- [ ] شغّل:

```powershell
npm.cmd run test
```

- [ ] إذا لم توجد ملفات اختبار بعد، اعتبر رسالة `No test files found` نتيجة متوقعة وليست دليلاً على فشل التثبيت.
- [ ] تحقق مباشرة من النسخة:

```powershell
npx.cmd vitest --version
```

- [ ] شغّل فحص TypeScript والبناء:

```powershell
npm.cmd run build
```

- [ ] شغّل lint:

```powershell
npm.cmd run lint
```

**ملاحظة baseline:** سبق تسجيل أن `npm.cmd run lint` قد يفشل إذا لم يكن `oxlint` متاحاً في PATH. ميّز بين هذا العطل البيئي وبين أي خطأ سببه Vitest، ولا تعتبره فشل Vitest.

## Task 4 — التحقق من عدم وجود آثار جانبية

- [ ] افحص `git diff -- package.json package-lock.json` إن كان Git متاحاً.
- [ ] تأكد أن التغيير يقتصر على dependency/lockfile أو إعداد اختبار مبرر فقط.
- [ ] تأكد أن `src/` لم يتغير.
- [ ] لا تُحدّث `AGENTS.md` أو خطة التطوير العامة إلا لإضافة ملاحظة تحقق قصيرة عند الحاجة.

## معايير القبول

تُعد المهمة مكتملة فقط عند تحقق جميع البنود التالية:

- [ ] `vitest` مثبت فعلياً أو ثبت أنه مثبت مسبقاً ومتزامن.
- [ ] `package.json` يحتوي `vitest` ضمن `devDependencies`.
- [ ] `package.json` يحتوي سكربت `test` يشغّل `vitest run`.
- [ ] `npm.cmd run test` تم تشغيله وتوثيق نتيجته.
- [ ] `npx.cmd vitest --version` يعرض نسخة قابلة للتشغيل.
- [ ] `npm.cmd run build` يمر بنجاح.
- [ ] نتيجة lint موثقة، مع فصل مشاكل البيئة عن مشاكل الكود.
- [ ] لا توجد تغييرات غير مقصودة في كود التطبيق.

## حالات الفشل والتصرف المطلوب

| المشكلة | التصرف |
|---|---|
| `npm.ps1` محظور | استخدم `npm.cmd` و`npx.cmd` فقط |
| `vitest` موجود في package.json لكن `npm.cmd ls` يفشل | نفّذ `npm.cmd install -D vitest` ثم أعد التحقق |
| فشل dependency resolution | سجّل الخطأ والنسخ المتعارضة، ثم توقف قبل استخدام force flags |
| لا توجد ملفات اختبار | لا تنشئ اختباراً عشوائياً؛ سجّل `No test files found` وانتقل لمهمة كتابة اختبارات Domain |
| فشل build بعد التثبيت | افحص `git diff` وأزل أي تغيير غير مرتبط؛ لا تخفِ الخطأ |
| فشل lint بسبب غياب oxlint | سجّل فشل البيئة، ولا تنسبه إلى Vitest |
